# ALU Regex Data Extraction

A Python script that extracts structured data (emails, credit cards, URLs, and phone numbers) from raw, unstructured text, with validation and security checks built in.

## What it does

The script reads a raw text file and extracts:

- **Emails** - including special classification for ALU-specific domains (alueducation.com, alumni.alueducation.com, si.alueducation.com)
- **Credit card numbers** - validated using the Luhn algorithm, and masked in the output (only the last 4 digits are shown)
- **URLs** - both http and https links
- **Phone numbers** - in various formats (with parentheses, dashes, spaces, and international + prefixes)

## How to run it

1. Make sure Python 3 is installed.
2. From the project root, run:
   python src/main.py
   (or py src/main.py on Windows if python is not recognized)
3. The script reads input/raw-text.txt and writes results to output/sample-output.json.

## Regex approach

- Email pattern: matches a username part, an @, and a domain made of letters and dots, with a final letters-only segment to avoid capturing trailing punctuation.
- Credit card pattern: matches groups of 4 digits separated by optional spaces or dashes.
- URL pattern: matches http or https, followed by ://, followed by non-space characters, excluding trailing periods and HTML tag characters.
- Phone pattern: matches an optional leading + or parenthesis, followed by digits, spaces, dashes, and parentheses.

## Security considerations

- Credit card validation: every matched card number is run through the Luhn algorithm before being accepted. Numbers that fail this check are rejected and never appear in the output.
- Credit card masking: valid card numbers are never shown in full in the output, only the last 4 digits are displayed.
- Malformed and hostile input awareness: the sample input text includes deliberately malformed and suspicious entries (a broken email, a script-injection-style string, a SQL-injection-style string, and an oversized junk string) to test that the extraction patterns do not treat these as valid data.

## Files

- input/raw-text.txt - sample realistic text used for testing extraction
- src/main.py - the extraction, validation, and output logic
- output/sample-output.json - example output generated by running the script
